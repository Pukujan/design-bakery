## Changes Made

### 1. The deploy kit runs on macOS (the only code change)

- **`flock(1)` is Linux-only.** The lock added in TASK-DB-0081 (to stop the deploy
  collision that 502'd `/api/*`) was `exec 9>"$LOCK_FILE"` + `flock -n 9`; the
  first Mac run died with `deploy.sh: line 137: flock: command not found`.
- **Docker Desktop is not on the non-interactive SSH PATH.** The Mac is driven
  over plain SSH, and `ssh mac <script>` has no `/usr/local/bin`, so `docker`
  resolved to nothing even though a login shell finds it.
- **Fixes** in `deploy.sh`, `rollback.sh`, `autodeploy.sh`: prepend
  `/usr/local/bin` to `PATH` after `set -euo pipefail` (harmless on Linux), and
  replace the flock with a portable **lock directory** (`acquire_lock()` in
  `deploy.sh`/`rollback.sh`): atomic `mkdir`, holder writes `pid` inside, EXIT
  trap removes it. Stale rules: dead pid (or pid older than
  `STALE_LOCK_MAX_MINUTES`, 24 h) is taken over; no-pid-yet lock only after
  `STALE_LOCK_MINUTES` (60 m); a leftover plain FILE at the lock path (the old
  flock scheme) is removed on sight. Still non-blocking — a live lock fails fast
  with the same message the timer relies on.
- **Bug found by testing:** the EXIT trap first used `rmdir`, which only removes
  empty dirs — but the lock dir holds the pid file, so the lock would have been
  left behind on **every** run. Changed to `rm -rf`; verified gone after a run.
- Header comments and `usage()` `sed` line ranges were kept line-count-neutral
  (verified with `--help` on the Mac).
