## Summary

Built the reusable research chart component for papers (TASK-DB-0054 / #49): a ```chart fenced
block carries a JSON spec, the dataset loads lazily from `/research/data/<id>.json`, and the
chart renders as hand-built React SVG on `d3-scale` / `d3-array` / `d3-format`. The same render
function runs in Node at build time to produce the static light/dark fallback SVGs. Also added
the data sync + type generation + validation scripts and the three CI drift checks that go with
them.

## Changes Made

### 1. Chart module — `frontend/src/app/modules/research/chart/`

- `spec.ts` — the fence spec: `data`, `metric`, `type`, `level`, `facet`, `filters`, `entities`,
  `highlight`, `colorBy`, `sort`, `controls`, `caption`, `height`. Parse + validate in one place,
  shared by the browser, the validator and the static renderer. Level-aware facet scope
  (`breakdown` → slice dimension, `experiments` → entity dimension).
- `compute.ts` — pure `computeChartModel(dataset, spec, state)`. The only place a number is
  produced. Reads `dataset.observations` field for field; never averages across entities.
- `ResearchChartSvg.tsx` — pure SVG, `colors` + `colorMode` (`css` | `light` | `dark`). Horizontal
  above 560px, stacked label-above-bar at or below it, labels never rotated.
- `ResearchChart.tsx` — reader state (metric, level, type, sort, filters, active row),
  `ResizeObserver` width, hover/tap tooltips, keyboard navigation, table fallback, CSV download.
  `React.lazy`-loaded.
- `ResearchChartEmbed.tsx` — loads the dataset lazily and keeps the build-time static SVG until
  the interactive chunk is on screen (and if it never arrives).
- `dataset.ts` — resolves an id through `/research/data/index.json`, flat `<id>.json` fallback.
- `theme.ts` + `globals.css` — `--rc-*` tokens, light and dark; component styles under `.rc-*`.

### 2. Fence → page

- `ResearchPaperPage.tsx` — `chart` branch in the markdown `code` override, plus `ChartSpecError`
  so a bad spec shows the author what is wrong instead of blanking the article.
- `content/db-r-2026-010.md` — one demo ```chart block (the only change to that file).

### 3. Build pipeline — `scripts/`

- `research-sync-data.mjs` — copies Eval Lab `paper/data/` into `frontend/public/research/data/`
  and verifies every sha256 against `index.json`.
- `research-gen-types.mjs` — regenerates `chart/types.generated.ts` from the JSON Schema.
- `research-validate-charts.mjs` + `research/chart-pipeline.mjs` — validates every fence, verifies
  the data hashes, and renders the static SVGs + `manifest.json` from the same React component the
  browser uses (esbuild bundle, React included).
- All three support `--check`; wired into frontend `prebuild` / `predev` and into CI.

### 4. Tests

- `scripts/test-research-charts.mjs` (`pnpm test:research-charts`) — pins the row key sets, checks
  every row against the published observation it came from, and covers spec parsing, facet scope,
  filters, sorting, layout at/above/below 560, static SVG colours, CSV shape, fence detection,
  slug purity, and CSS/`theme.ts` palette drift.
