## Session 2 — the copilot's cost and answer length (afternoon)

**Trace evidence.** The copilot's Phoenix spans are readable through Octo
(`GET /api/workspaces/<id>/otel/read/spans`). Eleven turns, 39 spans: about **180k prompt
tokens against 4k completion** (~45:1), an 8,130-token prompt for a bare "Hello", and
48,885 for the tour across six tool steps. Output was short in tokens and long in
characters, because one turn streamed its own reasoning before answering.

**Fixes.** An instant answer tier ahead of the model (`answers.ts`, nine intents, no
model call), a streaming filter that cuts leaked `</think>` blocks and pre-tool narration
(`textFilter.ts`), the site brief trimmed to roughly a third, and the visitor's page moved
out of the system prompt into the last user message so the prompt prefix stays stable for
provider caching. Both new modules have tests built from the real trace text
(`pnpm test:copilot-answers`, `pnpm test:copilot-stream`).

**Deployment.** The durable rate-limit migration (`011_copilot_rate_limit.sql`) had never
been applied and no `COPILOT_*` secret existed on the host, so the deployed `/chat` would
have answered `503` to every visitor. The migration is applied and both secrets are set.
The voice service at `copilot.design-bakery.com` answers with the grant shape the backend
validates.

**Security.** The octo workspace identifier was committed in ten places; it is now
redacted from every tracked file in favour of a pointer to `OCTO_WORKSPACE_ID`. It remains
in git history, which needs an owner-approved history rewrite to remove.
