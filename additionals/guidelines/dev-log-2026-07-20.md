## Case-study C rebuild (Opus)

Full requirements-driven rebuild of Cortex layout **C** (was only a declutter pass over
B). C is now a distinct third design an owner can pick against A and B, not a lighter B.

- **Design thesis.** *The receipt ledger* — the case study is read as an append-only audit
  ledger. Every reliability claim carries an honest status stamp (**built / partial /
  blocked / target**), defined once in a legend and reused as the organizing spine of both
  pages. One deliberate accent: an ochre **authority seal** (static SVG, "authority outside
  the builder"), plus perforated receipt edges. No canvas/CRT layer.
- **Distinct from A and B (so the A/B/C pick is real).** B is a dark, cool-slate, multi-
  panel instrument magazine with a canvas hero. C is **light-first** (warm paper default;
  dark mode via `data-theme` + `prefers-color-scheme`), **single reading column**, document/
  ledger rhythm, and a stamp-and-seal surface. Fewer competing panels than B: dropped B's
  full-bleed hero animation and 5-column architecture-comparison grid; folded prior-art from
  four cards into one condensed lineage list; kernel mechanisms became a dotted-leader ledger
  with `<details>` progressive disclosure for each honest caveat. Fonts stay IBM Plex (shared
  product family across A/B/C); hierarchy, type scale, and section rhythm differ.
- **Product truth held to B's bar (no invented metrics, no false "live in production").**
  Carried B's exact honest claims: `authorize()` component-tested but runtime-unwired;
  `tool_broker`/`human_control`/`receipts` partial (composition accepts a local callback,
  no broker apply path, no exact-diff authority receipt); isolation + oracles target/not
  live; `state_engine` recovery **nonconformant → Blocked**. Recovery replay keeps the
  **frozen v1.4 decision** explicitly separate from the nonconformant composition
  ("the nonconformance is in the composition, not in the frozen amendment"). Status totals
  reuse B's real figures (v1.4, 845+1s, 8/8 focused, 0 production runs) with no new numbers.
  Failure-mode vocabulary only (defect, stale, refusal, blocked) — no offensive-security
  framing. The "Target" legend line literally reads "…not yet implemented or live in
  production", so the one "live in production" string on the page is a negation, not a claim.
- **Pages.** `c/index.html` — masthead + status legend, then ledger entries 01–06 (problem,
  the OS move, kernel ledger, recovery replay, status truth, lineage), CTA to specs.
  `c/specs.html` — spec sections 01–07 with a sticky **chip index** (distinct from B's left
  TOC), a responsive **HTML** lifecycle (numbered vertical ledger, not a horizontal-only
  SVG), the illustrative `on_proposal` block (labelled illustrative), invariants I1–I11, and
  a module table with `<caption>` + `scope="col"`/`scope="row"`.
- **Accessibility.** `<main>` landmark, skip link, `:focus-visible`, semantic sections,
  `prefers-reduced-motion` (seal set-in + scroll reveals disabled), captioned/scoped data
  table, `html{overflow-x:clip}` backstop on both pages, wide table + chip nav + code block
  scroll inside their own frames rather than the page.
- **Switcher/theme.** Floating A|B|C switcher on both pages; consistent `localStorage`
  keys — `cortex-case-ver` (layout, active = C) and `cortex-theme` (shared with A/B so the
  theme choice persists across layouts). C's switcher label updated to "receipt ledger" on
  the C side only; A/B files untouched. Root `cortex/index.html` redirect already honours
  `cortex-case-ver`, so it will land on C after a visit.
