## Changes Made

### 1. Modularization phase 2 — delete dead code (TASK-DB-0069, #82)

- The orphan detector reframed issue #78's step 5: the four `frontend/extras/*`
  case-study apps are **live** (reached from `frontend/src` via their aliases), but
  their shadcn `ui/` subtrees are not imported at all. Fix was deletion, not a shared
  package.
- Deleted **250 files** (185 extras `ui/`, 23 other extras dead files, 36
  `frontend/src` shadcn, 6 small modules).
- Total CSS **671.4 → 334.3 kB** (−50%). Each case study's Tailwind entry
  (`@import 'tailwindcss' source(none); @source '../**/*.{js,ts,jsx,tsx}'`) and
  `frontend/src/styles/index.css` both scanned the dead trees, so removing the files
  dropped those utilities from both. JS unchanged — the files were never imported.
- Fixed two `scripts/find-orphans.mjs` bugs that mis-reported live backend files on
  Windows: the `services/lib` → `services/src` rewrite was separator-sensitive, and
  the compiled `lib/*.js` was tried before the source.
- Verified in a browser (Playwright against the built `dist`): `/`,
  `/case-studies/ekagajpatra`, `/case-studies/invest-ai`, `/case-studies/ai-agents/v3|v4`
  all render with no console errors; screenshots confirm no visual regression.

### 2. Orphan detector → strict required gate (TASK-DB-0070, #83)

- Added an `ALLOW` list to `scripts/find-orphans.mjs` for the 12 intentional keeps
  (`photo-gallery/**` is unrouted WIP for open issue #24; kit `examples/**` are
  reference examples). `--strict` now fails only on an **unexpected** orphan.
- CI `orphans` job switched to `node scripts/find-orphans.mjs --strict`; added it to
  `main`'s required status checks (alongside `quality`).
- Proven: a planted probe file made strict exit 1; removing it returned 0.

### 3. Backend container for gravebuster (TASK-DB-0071, #84)

- `deploy/gravebuster/Dockerfile.api` + an `api` compose service on
  `127.0.0.1:${API_HOST_PORT:-8788}:8787`, secrets from an optional git-ignored
  `.env.api`. `deploy.sh`/`rollback.sh` address `web` explicitly, so the frontend
  deploy is untouched.
- Build parity with Railway (`backend/railway.toml` + root `nixpacks.toml`):
  `pnpm install --frozen-lockfile --prod=false`, build services then backend, run
  `node backend/lib/server.js`; runtime installs `fontconfig` + `fonts-dejavu-core`.
- Verified locally: image builds, `GET /health` → 200 in ~2 s, healthcheck settles
  healthy, and the startup log shows `[publish-kit:fonts] using system DejaVu Sans` —
  the same font path Railway takes.
- Caught by running it, not by the build: the first image shipped without a `CMD`
  and exited 0. `CMD ["node", "backend/lib/server.js"]` now matches Railway.

### 4. TypeScript alignment (TASK-DB-0072, #85)

- `backend` and `backend/services` moved from `^5.8.3` to `^6.0.3`, matching the
  frontend. The plan warned TS 6 might flag new backend errors; it does not — both
  `tsc` runs are clean. Lockfile drops `typescript@5.9.3`; one version repo-wide.

### 5. CI trigger fix (context, merged earlier today)

- `.github/workflows/ci.yml` now triggers on **every** PR. Previously
  `on.pull_request.branches: [main]` meant stacked PRs ran no CI at all, which is why
  PRs sat unmerged — not an auth/approval requirement (`main` requires 0 approvals).

### 6. Public image uploads onto Octo files (TASK-DB-0074, continued)

- An upload lands in the private `octo` bucket, then `POST /api/files/:id/publish`
  copies that one object to `octo-public`. The stored URL is
  `https://files.design-bakery.com/<fileId>`. Signed links are not stored.
- `GET /api/public/assets/:fileId` remains for a URL already saved in that shape.
- Call sites: `mediaStorage.ts`, `coverStudioStorage.ts`, `publishKit/storage.ts`,
  `heroCache.ts`. A non-UUID `storage_path` is still deleted via Supabase.
- The workspace key can publish and unpublish. It cannot delete, so removing a
  public asset clears the public URL and then returns 403 on the private object.
- `--apply` rewrote 193 Supabase Storage URLs (28 posts, 31 media, 30 cover-studio).
  None of those tables still contain a `supabase.co/storage` URL. A sample cover
  returned HTTP 200 `image/png` from `files.design-bakery.com`.
