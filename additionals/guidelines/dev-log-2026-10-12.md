## CD on the Mac (TASK-DB-0086)

Owner direction: "create a cd pipeline for auto deployments". A merge to `main` now deploys
itself on the Mac within ~5 minutes, closing the gap this log had recorded as open.

`deploy/gravebuster/launchd/com.designbakery.autodeploy.plist` is a per-user launchd agent
(`StartInterval=300`, `RunAtLoad`) that runs the existing `autodeploy.sh` — the macOS
counterpart of gravebuster's systemd timer, modeled on the `com.octo.autodeploy` agent
already on that box. **No script changes were needed:** `autodeploy.sh` was already
macOS-portable (TASK-DB-0082), and `deploy.sh` writes `SHA=` to `.deploy-state` only after
green smoke, so a failed deploy is retried on the next tick instead of being recorded as
done.

Mechanisms offered, and why the agent won:

- **launchd agent (chosen)** — no secrets, no inbound access, reuses `deploy.sh`'s lock,
  smoke and auto-rollback.
- **GitHub Action over Tailscale + SSH** — needs a Tailscale OAuth client minted in the admin
  console plus an SSH key as a repo secret, for no functional gain.
- **Self-hosted GitHub runner** — the repo is **public**, and GitHub advises against
  self-hosted runners on public repos (a fork PR that edits a workflow could execute on the
  box, which also runs several other stacks this deployment must not disturb).

The one dependency worth remembering: the Mac has **no `gh`** and `origin` is HTTPS, so the
poller authenticates through the login keychain (`credential.helper=osxkeychain`) — the same
path `com.octo.autodeploy` uses.

**Verified:** `plutil -lint` OK; `autodeploy.sh --dry-run` reported the correct pending move;
then installing the agent deployed `bc7512a` **on its own**, no hand run —
`deploy OK: bc7512a975a1 -> design-bakery-web:bc7512a975a1-20261012T184332Z`, every smoke
line green including `ok 200 /api/public/blogs (caddy proxy + data layer)`. Public edge
afterwards: `/` 200 shell, `/version-2` 200 journey, `/version-2/plate-arrival.png` 200,
`/healthz` 200.

Then the acceptance test — a **second** cycle on the timer rather than on load: merging #118
moved `main` to `54624ca`, and the agent's next tick picked it up unattended
(`[18:49:12Z] new commit on origin/main: 54624cae8e4f (deployed: bc7512a975a1)`), advancing
`.deploy-state` to `SHA=54624ca…` — a value `deploy.sh` writes only after green smoke.
`launchctl print` reads `runs = 2`, `last exit code = 0`. Two cycles is what distinguishes a
recurring poller from a one-shot `RunAtLoad`.
