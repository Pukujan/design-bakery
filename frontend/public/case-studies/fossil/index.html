A problem hiding inside AI-assisted work

You remember the decision.
You don't remember how you got there.

Three weeks ago you compared options, read docs, ran tests, changed an assumption and finally chose an architecture. Today the code is drifting. You can still see what you chose. The hard part is reconstructing why.

The premise

Git keeps the code. Tickets keep work items. Chat history keeps conversation. AI memory can help recall. None of those guarantees that the evidence and reasoning behind a decision remain reconstructable.

The actual loss

The answer survives. The chain gets scattered.

A serious decision is rarely one sentence. It is a trail of evidence, alternatives, failed attempts, assumptions and changes in belief.

At the time

The reasoning is obvious because it is in your head and in the active context around you.

After a break

You search commits, tabs, chats, tickets and memory. You may recover the answer. Recovering the exact path is a different problem.

This is not just a personal annoyance

Software research has been measuring pieces of this problem for years.

These studies do not prove FOSSIL. They establish that resuming work, finding rationale and using long histories are real failure points.

Memory is useful. It is not provenance.

“The AI remembers” is not the same claim as “we can verify why.”

This is not an argument against memory. Memory is useful for recall and personalization. FOSSIL is aimed at a different guarantee.

The useful difference: an answer can be fluent and still be wrong about its own history. FOSSIL keeps the historical objects separate from the model that explains them.

What the product does

FOSSIL gives the project an epistemic history.

It preserves not only what was concluded, but what the conclusion depended on and how that state changed over time.

Exact evidence

Source snapshot, immutable bytes, exact citation span, content hash and retrieval time.

Typed disagreement

Support, challenge and contradiction stay separate. The system does not need to manufacture consensus.

History without rewriting

Superseded ideas remain queryable, so “what did we believe then?” is different from “what is current now?”

Adversarial review

What FOSSIL does not get to claim.

A provenance system should be held to the same standard it asks of everyone else.

It cannot preserve reasoning that was never captured.

FOSSIL reconstructs recorded evidence and lineage. It does not read minds or recreate missing private thoughts.

A source is not truth because it has a hash.

Integrity tells us which bytes we used. Source quality, independence, timeliness and applicability are separate questions.

Model confidence is not knowledge state.

Retrieval rank, similarity, agent agreement and confidence are signals. They do not get to silently promote a claim into truth.

Internal benchmark · small by design

The most useful FOSSIL benchmark started with a failure.

This is an internal six-case real-corpus benchmark, not independent validation. We keep it because the failure shows the exact problem FOSSIL is meant to prevent.

Initial run
5 / 6

A stale dependent claim fell outside top-k retrieval. The answerer selected an unrelated supported claim and answered with confidence 1.0.

Same cases after lineage fix
6 / 6

Stable relation endpoints were resolved from durable lineage before answer generation. The missed case became current_state_unresolved with its exact citation.

Internal result, 2026-08-10. The point is not “100%.” The point is that retrieval was not allowed to become historical authority.
