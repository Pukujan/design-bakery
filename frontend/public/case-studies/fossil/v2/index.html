A problem hiding inside AI-assisted work

You remember the decision.
You don't remember how you got there.

A few days ago you read the docs, compared options, ran a test, changed an assumption and picked an architecture. Today you can still find the answer. Rebuilding the chain that made the answer make sense is harder.

The premise

Git keeps code. Tickets keep work items. Chat keeps conversation. AI memory helps recall. None of those, by itself, promises that the evidence and changing reasoning behind a decision remain inspectable later.

What actually disappears

The decision was never just “choose B.”

Real technical decisions are trails. The source, the assumption, the failed attempt and the objection often matter as much as the final choice.

The market is not empty

Good products already exist on both sides of this problem.

That is a stronger starting point than pretending FOSSIL invented memory or decision records.

Agent memory

Mem0, Zep/Graphiti and similar systems persist facts, temporal context and graph relationships so an agent can retrieve useful context later.

Decision memory

ADR tools such as adrkit, plus platforms like Ardoq, preserve decisions, rationale, alternatives, status and the “graveyard” of old choices.

Decision intelligence

Cloverpop treats decisions as a system of record: what was decided, why, by whom and what happened afterward.

FOSSIL's bet

The missing layer is the path underneath the decision: source-grounded claims, assumptions, experiments, opposition, dependencies and state changes that can still be inspected later.

Adversarial review

What FOSSIL does not get to claim.

“It recreates everything.”

No. If reasoning was never captured, FOSSIL cannot invent it later.

“A hashed source is true.”

No. A hash proves which bytes were used. Authority and relevance remain separate questions.

“FOSSIL has no competitors.”

No. Memory systems, ADR tools and decision-intelligence platforms overlap materially. The product has to prove its narrower contract.

Internal benchmark · not third-party validation

The most useful FOSSIL benchmark started with a failure.

Six cases are not a market benchmark. The value of this test is that the failure exposed exactly what happens when retrieval is allowed to stand in for history.

5 / 6

Initial run

A stale dependent claim fell outside top-k. The answerer picked another supported claim and returned confidence 1.0.

6 / 6

Same cases after lineage resolution

Durable relation endpoints were resolved before answering. The missed case became current_state_unresolved with exact citation.

The lesson

Not “100% accuracy.” The lesson is that retrieval was not allowed to rewrite the project's history.

The simplest version

Git tells you how the code changed. FOSSIL tells you how the knowledge changed.

Not better memory. A durable, inspectable history of the evidence and reasoning that mattered.
