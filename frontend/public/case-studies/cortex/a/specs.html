01System model

Cortex is organized as planes of modules, each governed by a frozen contract. The kernel is the trust root every later plane stands on.

Nothing an agent proposes reaches the repository directly. An agent runs in a sealed container holding zero credentials and submits a typed proposal over one mediated channel. One privileged process, the broker, is the only writer. It loads the owner-frozen contract for that work-unit, runs the proposal through the reference monitor, materializes an approved change only through the monitor's canonical mapping, and opens a pull request. Merge waits on a deterministic verdict from a separate identity.

The kernel itself is the one acknowledged exception to contract-first construction: the machinery that enforces contracts cannot enforce its own creation, so Phase 0 is built by hand under a declared temporary mode with the human as manual contract authority. From Phase A onward, contract-first applies with no exceptions.

02The reference monitor

authorize() is a pure, deny-by-default function. It's the single gate every mediated request and every worktree pull has to pass.

It takes a proposal and the frozen contract and answers one question: may the broker materialize this change? No model, no judge, no I/O touches the verdict. The broker does the filesystem resolution and hands in the resolved paths, so the monitor is pure judgment over strings. It canonicalizes every proposed path (Unicode normalization, separator and verbatim-prefix handling, lexical traversal collapse), cross-checks it against the broker-resolved form, and admits a write only if it lands inside the contract's frozen write-set and clears a set of never-exempt forbidden prefixes. A proposal carrying unresolved unknowns is denied outright. Guessing is not a legal move.

The monitor runs against a frozen corpus of nasty path forms: directory traversal, symlink escape, case-fold collisions, Windows reserved device names, alternate-data-stream targets. That corpus grows every time an adversarial pass finds a new one.

The same flow, in shape

on_proposalillustrative · not the implementation
# the gate every agent proposal passes. deny by default.
def on_proposal(env):
    if not registry.valid_token(env.worktree, env.token):
        return deny("TOKEN_INVALID")         # not your sandbox
    if registry.work_unit(env.worktree) != env.work_unit:
        return deny("WORKTREE_MISMATCH")     # not your work-unit
    plan = contracts.frozen_plan(env.work_unit)
    if plan is None:
        return deny("PLAN_NOT_FROZEN")       # no freeze, no work

    v = authorize(env.paths, plan)           # declared intent
    if v.denied: return deny("AT_RECEIVE", v)

    resolved = broker.pull(env.worktree, env.paths)
    v = authorize(resolved, plan)            # use-time: catch a swap
    if v.denied: return deny("AT_PULL", v)      # symlink / repath escape

    broker.materialize(v.canonical_map)      # only via the monitor's map
    return broker.open_pr(...)             # merge waits on a verdict
    # every branch above leaves a receipt (I11)

Simplified for reading. The real module is pure (no I/O in the verdict), the receipt write is atomic with each branch, and the two authorize calls are the same function over declared then resolved paths.

03The invariants

Eleven mechanically-testable properties. Together they are the acceptance checklist and the daily self-test's assertion list.

  1. I1No agent credentials. No repo, API, or signing credential is ever in an agent container's filesystem, environment, or reachable network.
  2. I2Sole writer. Only the broker writes the repo. Agents cannot push, and the broker only opens pull requests, never direct pushes to protected branches.
  3. I3No self-assigned privilege. Trust label, tier, and code-origin come from the path and the broker's own dispatch record, never from agent-supplied metadata.
  4. I4Verdicts verify themselves. The required merge check re-fetches and hash-verifies the evidence against the exact commit; verdict identity is distinct from PR-author identity, and neither can approve.
  5. I5Boundary paths need a human. Any diff touching the contract, kernel, or CI paths requires owner review; in-scope diffs auto-merge on a green verified check only.
  6. I6Out-of-write-set never becomes a PR. Denied at receive; widening scope is a new owner-frozen plan.
  7. I7Isolation never degrades. A workload that cannot run at its assigned grade fails visibly; it is never demoted to a weaker sandbox.
  8. I8Read-back is the only truth. No inbound webhook listener exists; any future event is a hint that triggers an API read-back, never a fact.
  9. I9Keys off the execution host. No key material ever resides where untrusted code runs.
  10. I10Unresolved unknowns block mutation. A mutating proposal with open unknowns is denied. That's enforced by sequencing, not by appeal to the model's intent.
  11. I11Every privileged event leaves a receipt. Freezes, approvals, PR opens, verdicts, merges, denials, worktree lifecycle events. Each one is minted only by the broker or oracle process.

05The trust-critical build lane

How a kernel module gets built so that an independent adversary, plus the owner reviewing the boundary, couldn't find a gap in it.

  1. Two independent authors.

    One model writes the tests and an adversarial input corpus. A separate model writes the code. Neither sees the other's work, and both work only from the frozen contract. When they agree on first contact, that's the trust signal.

  2. Adjudicate, don't assume.

    The orchestrator checks the strongest claims against the source and sorts each disagreement into one of three buckets: a real defect, a hardening, or a contract ambiguity to reconcile. Changing frozen behavior is the owner's call.

  3. Sealed-holdout ratchet.

    A third model writes an adversarial holdout that lives outside the repository, where no agent can study it. It has to kill 100% of seeded regression probes and surface gaps the visible tests missed. Every gap it finds becomes a permanent open test, so the module only ever gets stronger.

  4. Ship through the real gates.

    The change lands as a pull request authored by the broker's own identity, reviewed and approved by the owner. The system governs its own construction. Code, tests, contract, and receipt move together.

06Verification & evidence

Deterministic where possible; a judge only where syntax genuinely cannot decide.

Every verdict emits a universal evidence bundle (exact model id, commit, image digest, dataset and oracle version, artifact hashes, verdict, abstention). The broker stores it on a dedicated branch, a separate oracle identity hash-attests it, and a required CI action re-verifies it independently. A daily canary runs the whole path through the real machinery and pages the owner if any gate has gone soft. A module isn't "done" until that canary runs green three days straight.

On this project the sealed-holdout ratchet has already found a receipt-replay hole and eleven path-and-authz gaps in code that had passed every visible test and merged. The slow adversarial verification isn't overhead. It's the product.

07Threat model & honest residuals

The current posture is reliability-now, security-ready. The adversary we model is a faulty or lazy agent reaching somewhere by accident, not a determined attacker.

A few residuals are accepted for now and written down rather than hidden, each with a named hardening step on the ladder to a stronger posture. A determined sandbox escape could tamper with a sibling worktree on the same host (bounded by isolation grade and canary detection). Channel authentication is plain bearer tokens behind a swap-ready seam. The broker and canary live on the owner's machine, so work queues while it's off. The receipt mint is tamper-evident, keyed by a local secret. It is honestly not tamper-proof against someone who also holds that key.

The later planes (execution, knowledge, oracles, learning, comms) are designed at the master-contract level but not yet fully sub-contracted, so their scope isn't claimed as known. And the value of the whole thing is exactly proportional to whether the contracts capture real intent and the gates catch real failures. The rigor has to stay real, or it's just overhead.
