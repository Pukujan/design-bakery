The problem

To be useful, an agent has to be dangerous.

Every AI coding tool works the same way: hand the model your repository and your credentials, then hope.

From that moment it can read every file you own, and anything it reads can end up in a prompt to a company you do not control. It can write anywhere. It never gets tired, and it never asks twice.

01

Access is all or nothing

The task needed four files. You handed over forty thousand.

02

Your code becomes their input

Once it is in the prompt it has left your building. No test undoes that.

03

Approving every step is not automation

A human clicking yes on each change is just a slower developer.

So the people who need this most cannot buy it. Law firms, banks, hospitals, defence suppliers, and every startup whose code is the company.

Why now

The models got good. The guardrails did not.

Two years ago agents were a demo. Today they close real tickets, and every serious engineering team is piloting them.

Adoption is running years ahead of control. Companies are choosing between moving fast with no safety net and standing still while their competitors do not. That gap is the opportunity, and it is open right now.

  • ✓Capability arrived. Agents work for hours unattended and produce real output.
  • ✓Budget arrived. AI is a board-level line item, not a side experiment.
  • ✗Trust did not. There is still no standard answer to "what exactly can it touch?"
  • ✗Regulation is closing in. New AI rules, sector regulators and client contracts all want that answer soon.

Every wave of computing eventually gets its permission layer. Mobile got the app sandbox. Cloud got IAM. Agents have not got theirs yet.

The insight

Separate the thinking from the authority.

The model is brilliant and should never be trusted. So we stop asking it to be trustworthy, and take the power away instead.

The AI proposes. Something else decides. That second thing runs on your machine, holds every credential, and answers only to you.

How it works

Three steps. One approval.

1

You set the boundary

What the agent is trying to do, which files it may touch, and what counts as finished. It takes a minute, and you do it once.

2

The agent works, unsupervised

No approval prompts, no babysitting. It reads, writes, runs the tests and fixes what it broke, all inside the boundary.

3

Anything outside it stops

A file it was not given, a wider permission, data that should not leave. It stops and asks you, instead of deciding for itself.

The difference from a sandbox: a sandbox contains damage. Cortex controls authority. The agent is not locked in a room. It simply never had the keys.

The wedge

Your code never has to leave the building.

The obvious objection: how can a cloud model help with code it is not allowed to see?

Because most work needs the shape of a problem, not its contents. You can write a function that processes client records without ever seeing a client record. Cortex prepares that version of the task, sends only that, and fits the result back against the real code on your machine.

→

What goes out

Interfaces, structure, a clean description of the problem. Checked before it leaves.

⋮

What stays

Source, customer data, secrets, and everything the business actually runs on.

∅

What we refuse

If a job truly needs the sensitive material, it runs locally or not at all.

That last one is the product. A boundary that can be talked around is not a boundary, and it is the first thing a serious buyer tests.

Why it holds

Hard to build. Harder to bolt on.

This is not a feature a coding assistant adds in a sprint. It is an architectural decision made at the start, and the incumbents made the opposite one.

  • ✓Their design fights it. Every major tool begins by giving the model the whole repository. Reversing that means rebuilding the product.
  • ✓Trust compounds. Once a security team signs off on a control layer, replacing it is a year of work nobody volunteers for.
  • ✓Model-agnostic by design. Whoever wins the model race, the boundary is still needed. We get stronger as they do.
  • ✓Regulation is a tailwind. Rules that make agents harder to deploy make a control layer mandatory rather than optional.

We win by being the piece everyone eventually needs and nobody wants to build: the layer that says no.
