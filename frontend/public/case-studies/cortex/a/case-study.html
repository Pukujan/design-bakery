Case study · research system

An evidence-gated harness for trustworthy autonomous AI.

A research system that tackles a hard question — can AI agents build and verify software autonomously without you having to trust their word? — and answers it with deterministic gates instead of faith.

My role Sole architect and director — architecture, verification methodology, orchestration.
Status Solo research system, active development. Not a shipped product.
Implementation AI agents, working inside a harness built to keep them honest.

Honest framing, up front

This is agent-orchestrated engineering. The contribution is the systems design and the verification discipline — not hand-written novel algorithms. Every number below is tagged by how well it is backed, and the tags are the point.

01 · the problem

Fluent, confident, and wrong is the dangerous combination.

Most agentic systems answer this by putting a human in front of every step. Cortex asks whether you can replace trust with mechanism.

What an agent will tell you

"The tests pass. I verified it end-to-end."

Both are things an agent will say whether or not they are true. Fluency is not evidence, and a confident report is the cheapest thing a model produces.

What the kernel requires instead

A machine-checkable artifact, or it did not happen.

A frozen contract, a sealed probe suite the builder never saw, killed mutants, and a deterministic checker's verdict. No step advances on an assertion.

02 · the approach

Three principles, each made mechanical rather than aspirational.

01

Contract-first

Freeze what "done" means — as a testable observable — before any code is written. An agent cannot move goalposts it cannot see.

02

Objective verification, not judgment

Where possible a deterministic checker, not another LLM, decides pass/fail. Gates that could be gamed get an adversarial holdout whose whole job is to try to game them.

03

Independence

The agent that builds is never the agent that verifies, and the verifier's tests are sealed from the builder — so it cannot fix-to-the-test.

03 · verification path

How a unit of work earns the word "done".

Nothing is accepted on an agent's report. A work unit advances only by passing gates that a machine, not a model, decides.

work-unit lifecycle · builder ≠ verifier deterministic verdict 
flowchart TD
  C["Contract frozen<br/>(testable observable)"] --> B["Builder agent<br/>writes implementation"]
  C --> H["Verifier agent authors<br/>SEALED holdout probes"]
  H -. "never shared with builder" .-> B
  B --> R{"Run sealed probes<br/>against blind build"}
  H --> R
  R -- "fail" --> F["Defect recorded<br/>· returned to builder"]
  F --> B
  R -- "pass" --> M{"Inject mutants:<br/>are they all killed?"}
  M -- "survivor" --> W["Probe suite too weak<br/>· strengthen and re-run"]
  W --> H
  M -- "all killed" --> D["Deterministic checker<br/>decides pass/fail"]
  D --> V[["Verdict + evidence ledger"]]
  F --> V

The two independent authors are the load-bearing part. Because the probe suite is written from the frozen contract and sealed before the build exists, a builder cannot tune to it — and because every injected mutant must die before a verdict counts, a suite that merely passes is not yet trusted.

This is not a hypothetical failure mode

The sealed holdouts repeatedly caught real defects the builder's own green test suite missed — including a floor-bypass defect that a 41/41-passing test-driven suite sailed straight past, and an owner-approval-gate bypass on a resume path. "Building to the test" was caught empirically here, not asserted.

The anti-gaming result: a hidden holdout that caught every gamed build

recomputed

The obvious failure mode of “make the tests pass” is a build that satisfies the visible suite without solving the problem. So the coding lane runs an adversarial experiment against itself: deliberately gamed implementations — visible-suite memorisers and seeded logic bugs — are submitted, and a hidden holdout suite the build never saw decides the verdict.

20 attempts. 16 passed the visible suite. All 16 were caught by the hidden holdout. 0 uncaught. That is the single strongest piece of evidence on this page, and it was absent from the previous version of it.

What this does and does not show. Re-run on 2026-07-26 with python -m evals.objective_coding.holdout_gaming → attempts: 20, gamed_attempts_passing_visible: 16, caught_by_holdout: 16, uncaught_by_holdout: 0, catch_rate: 1.0. The gaming strategies are ones I authored, so this measures the holdout against anticipated gaming, not against an adversary cleverer than the person who designed the trap. A perfect score here is a floor, not a proof.

Sealed-holdout verification with mutation testing

recomputed

A test suite that passes has not earned trust; a test suite that kills injected mutants has. Four oracle lanes — datetime, regex, ledger, invoice — are each cross-validated against an independently written second implementation, with mutants injected into the primary. Mutation score 1.0 on all four, n=71 scored negatives; checker agreement 1.0 on three lanes and 0.9762 on regex, whose single disagreement is a documented policy false-negative (a catastrophic-backtracking pattern), not an undetected defect.

The same discipline runs on the kernel itself: probe suites authored sealed, by an agent that is never the builder, and run against blind builds. Across four kernel modules every injected mutant died — contract-engine 10/10, human-control 13/13, broker 6/6, model_dispatch 5/5 off-ledger — and the holdouts repeatedly caught real defects the builder's own green suite missed: a floor-bypass that sailed past a 41/41-passing test-driven suite, and an owner-approval-gate bypass on a resume path (16/21 probes deterministic on double-run) off-ledger.

Where each number comes from. The mutation-score line is re-runnable: python -m cortex_core.oracle_crossval → four lanes, mutation_score: 1.0 each, 20+13+19+19 = 71 negatives scored. The kernel 34/34 figures are tagged off-ledger because they live in review write-ups (reviewed/scc-v2-*-review-2026-07-18.md) and have no row in evals/results.jsonl. They are real and cited; they are not sealed evidence, and this page will not pretend otherwise. Mutant sets are also hand-seeded: 13/13 means every failure class I thought of dies.

LLM-judge calibration — and finding that the gold my own pipeline produced was vendor-biased

prose-only

I measured judge reliability with Cohen's κ across versioned rubrics. A richer rubric lifted capable judges from κ 0.61 to 0.92 with the model held constant (n=18) — while the same rubric regressed a small 4B model from 0.60 to 0.52. The durable asset is the rubric, not the model. Both figures are prose-only: they live in the calibration report, with no committed artifact that reproduces them.

The sharpest result cuts against the model family I had chosen to build on. My gold labels were authored by Anthropic models; on a 28-record blinded panel of ten judges, Anthropic judges agreed with those labels at mean weighted-κ 0.947 versus non-Anthropic 0.426 — a gap of 0.522, recorded in the audit as an explicit self-preference flag. The strongest non-Anthropic judge reached 0.753, so the gap is partly capability rather than pure vendor bias — but a residual family gap remains, and the project's own conclusion is that the labels “have signal but are not vendor-neutral.”

Two corrections this rebuild made to its own page. (1) The earlier draft cited 0.95 vs 0.50. The committed artifact (evals/bias_reports/stage1_summary.json) says anthropic_mean_wk 0.9474, non_anthropic_mean_wk 0.4257, gap 0.5218 — the 0.50 came from a closeout's prose restatement, and the sharper artifact number is the one now shown. (2) The earlier draft attached “Prometheus κ = 0.000” to this same audit. It belongs to a different experiment — the 18-case calibration bias audit (calibration/results/BIAS-AUDIT.md), where Prometheus scores 0.000 and the file itself names that row as the clean family-bias test to read instead of the gentler family mean. In this 28-record panel Prometheus scored 0.519. Merging the two made the finding look sharper than any single experiment supports. Both figures are off-ledger — cited to committed files, but with no row in evals/results.jsonl.
The disposition that follows. The same artifact records hard_gold: 0 and safe_training_candidates: 0 — nothing from this pipeline was promoted to training gold, because the audit said not to. (It does record 20 cross_vendor_synthetic_gold records, so “zero promoted” is only true of the safe-training-candidate lane; the previous page's flat “0 records promoted” over-simplified.) The judge-free objective harness above exists precisely because this bias is, in the project's own words, unresolved without third-party gold. A separate faithfulness backend was rejected on the same principle: it agreed with human labels at 0.429, below the 0.744 majority baseline, and was refused registration rather than shipped as biased gold prose-only.

Multi-model routing calibration

off-ledger

A cheap model passed only 14/41 (34%) first-pass against a frozen oracle suite — with failures all logic-class, not interface crashes — while a stronger model repaired every failure to 41/41. That is the empirical basis for risk-tiered routing: expensive models run only where a task's measured difficulty demands it.

Tier. Sourced to reviewed/scc-v2-model-dispatch-review-2026-07-18.md and BUILD-ROUTING-CALIBRATION-2026-07-18.md, with no row in evals/results.jsonl. One model pair, one module — a calibration data point, not a routing law.

The gap this page is least comfortable showing

recomputed

The whole thesis here is that a claim without a machine-checkable artifact does not count. So the fair question is how well the project's own audit trail holds to that. Measured across every closeout in audit/audit-log-*/agent/ on 2026-07-26: 1,723 closeouts, of which 1,626 (94.4%) carry an empty or absent evidence[] array. Of the 219 whose tests field claims a passing run, only 31 attach a machine-readable test evidence item — 188 are prose assertions of exactly the kind the kernel is built to reject.

The structured-evidence schema arrived after most of that history was written, and the newer kernel work is gated mechanically rather than by closeout hygiene. But the number is what it is, and a page arguing for evidence discipline that hid its own worst compliance figure would be making the argument it claims to refute.

Method, so you can disagree with it. “Claims a pass” = the tests string matches pass|passed|passing|green|all tests and is not one of the explicit “not run / none” forms. “Grounded” = at least one evidence[] item with type == "test". Both are judgement calls in the classifier, and a looser or stricter reading moves the denominator by a few dozen; the 94.4% empty-evidence figure is a direct count and does not depend on them.

One more receipt, because it is the cheapest kind to check: sha256sum -c scratchpad/STORE1-HASH-MANIFEST-2026-07-25.sha256 → 450 files OK, 0 failed, re-verified 2026-07-26. The manifest covers artifacts that cannot be regenerated — sealed probe packs whose authoring seat is retired — so integrity is the only guarantee left available for them. recomputed

05 · what it demonstrates

Four capabilities, in order of how rare they are.

Evaluation engineering

Objective benchmarks, statistical calibration, adversarial verification. The rarest and most transferable skill in the set.

A verification instinct

Treating "the model said so" as worthless, and building the mechanisms that make autonomous work auditable.

AI systems architecture

A coherent multi-agent system with explicit authority boundaries and fail-closed behaviour.

Pragmatic AI engineering

RAG, retrieval tuning, cost and latency optimisation, model routing.

06 · honest limitations

What this is not.

Solo, research-grade, not production-hardened. Every metric is self-measured on this system and none is externally audited — which is exactly why each one above carries a committed-artifact, recomputed, reconciled, prose-only or off-ledger tag rather than being presented uniformly.

The honest split: the objective lanes, the hidden-holdout catch rate and the mutation scores are re-runnable from source; the calibration κ, the scope-pack cut and the retrieval deltas survive only as prose in agent-authored eval docs; and the kernel mutant counts and routing calibration are cited to review write-ups with no ledger row at all. The value here is a demonstration of how I approach trustworthy AI — not a claim of production scale. The methodology and the judgment are the transferable parts.

07 · how this document was checked

The write-up went through the same treatment as the system.

To avoid the exact failure this project studies, this case study was itself put through a cross-vendor adversarial audit — a panel of non-Anthropic models (GLM-5.2 / Zhipu and Gemini 3.5 Flash / Google) tasked to refute it against the repository's actual source files.

They found real problems — twice

The first pass caught a draft that cited the milder vendor-bias number and omitted the sharper self-preference finding. A later review caught something worse: the badge system itself. Two badges were standing in for the ledger's four provenance tiers, and the stronger badge had been assigned to two of the weakest rows — including a record count the ledger annotates as “STALE … does NOT match disk.” Both corrections are folded in above, along with the numbers that got smaller when checked (0.50 → 0.426) and the ones that had been quietly merged from two different experiments. A write-up that hid its worst number would have failed its own thesis.
