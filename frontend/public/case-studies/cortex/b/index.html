Case study · reliability infrastructure

CORTEX

A control plane for fallible AI agents.

Cortex makes scope, evidence, approvals, and failure states explicit. Models can change; the contract and verification path stay fixed. The result is lower-risk delegation with a human still owning intent and completion.

The problem

Capable is not the same as trustworthy.

AI coding agents remain probabilistic, so consequential output still requires verification proportionate to its risk. A stronger model can reduce errors, but it does not establish correctness or authority.

Ungoverned agent path

A better driver

A stronger model, richer prompt, or larger toolset may reduce errors, but without an independent control path the model's proposal can still become an action before an external authority verifies it.

Cortex

A control plane around the driver

Assume the agent is fallible. Put enforceable boundaries between proposals and consequential actions, bind approvals to exact artifacts, and keep independent evaluation outside the builder. The controls reduce risk; they do not certify the product by themselves.

The inversion

The move operating systems made fifty years ago, applied to AI agents.

You do not rely on every program to avoid corrupting memory; you put enforceable boundaries between programs and hardware. The target architecture applies that reference-monitor pattern to an agent acting on a repository. Cortex has component-tested kernel mechanisms, but the production agent path does not yet run through the composed kernel. Three commitments follow.

01 · before

Contract-first

Outside the declared manual Phase 0 bootstrap, the target process freezes the goal, write-set, and acceptance oracle before implementation. The reviewed composition path has not demonstrated a durable owner-frozen plan receipt.

02 · during

Deny-by-default

In the target path, every write, execution, or network action passes through the broker after deny-by-default authorization; only provably pure reads may run directly. Current OpenCode and agent-runtime paths are not yet behind that gate.

03 · after

Proof, not vibes

The target release path requires deterministic evidence verified outside the builder and receipts bound to the approved artifact. Verified failures may become durable gates after review and human promotion; neither the production merge path nor that learning loop is live end to end.

The kernel · component progress

Six mechanisms, with their integration state shown honestly.

Many kernel components are merged and component-tested. The reviewed composition branch remains blocked and is not ready for a pull request; production authority services and a live end-to-end canary are also incomplete.

built
authorize()

Reference monitor

The standalone component is a pure, deny-by-default path gate tested against difficult path forms. Current OpenCode and agent-runtime paths do not call it, and the reviewed composition calls it directly without a broker-mediated apply path.

partial
tool_broker

Sole writer

Target sole-writer process: it owns mutation credentials, authorizes at receive and use, applies approved patches, and opens pull requests. The reviewed composition path does not construct a broker envelope, call its proposal handler, or apply the patch.

merged
receipts

Content-bound receipts

Receipt components are merged and tested, but the reviewed composition path accepts an arbitrary callback result as its approval receipt and does not verify an exact-diff-bound human-control authority receipt.

designed
isolation

Trust-graded sandboxes

The target assigns isolation by workload risk and fails visibly when the assigned grade is unavailable; it must never silently weaken isolation. Production trust-graded sandbox execution is designed but not live.

merged
human_control

Approval bound to the diff

The human-control component is intended to bind an approval based on an independent summary and observed output to the exact diff. The reviewed composition path does not call that authority flow and instead accepts a local callback result.

not live
oracles

Evidence, not assertion

The contract requires deterministic checkers where possible, independent attestation, evidence-hash verification, and a universal evidence bundle. No live end-to-end evaluator path currently demonstrates those requirements.

The target learning loop fingerprints verified failures and drafts gate or oracle proposals. Promotion requires review and human approval; the end-to-end learning loop is not live.

Why this isn't a leap in the dark

Established mechanisms, recomposed for agent reliability.

The architecture draws from named reference-monitor, privilege-separation, content-binding, and workload-isolation patterns. The case study does not claim that precedent alone proves this implementation.

1972

The reference monitor

Anderson's study, then Saltzer & Schroeder (1975), established principles such as least privilege, complete mediation, and fail-safe defaults. Those principles influenced authorize(); they do not prove this implementation.

2003

Privilege separation

OpenSSH's tiny privileged monitor with unprivileged workers that hold nothing (Provos, Friedl, Honeyman, USENIX Security). The broker is this pattern.

2009

Capability & content binding

seL4, the formally-verified capability microkernel. Macaroons (Google, 2014). Merkle hashing, which binds a token to an exact hash the way git and Sigstore do. The receipt is this.

2020

Trust-graded isolation

Firecracker and gVisor provide established examples of stronger workload isolation. Cortex's proposed risk grading is its own composition of those patterns, and production execution is not live.

The design followed prior-art studies and independent critique before implementation. Existing parts were adopted where they fit and rejected with recorded reasons where they did not. The project claim is the composition and the evidence trail, not the invention of new primitives.
