01System model

The frozen master defines the target control and runtime spine. Its A–D modules have contracts; later execution, knowledge, oracle, learning, and communications planes remain staged for later freezes.

In the target system, a credential-free worker submits a typed proposal to a sole-writer broker. The broker loads the owner-frozen plan, authorizes the declared and resolved paths, materializes an approved change, and opens a pull request. Independent evidence and the required human authority then decide whether that exact artifact may merge.

The inspected reality is narrower. OpenCode and agent_runtime run beside the kernel, not through it. The reviewed composition calls the reference monitor directly, does not use the broker apply path, and stops after local approval. Phase 0 therefore remains a declared manual bootstrap rather than a self-governing production path.

02The reference monitor

authorize() is the pure, deny-by-default gate required by the target broker path. It is component-tested, but it is not yet the sole gate around current OpenCode, agent-runtime, or composition mutations.

It takes a proposal and the frozen contract and answers one question: may the broker materialize this change? No model, no judge, no I/O touches the verdict. The broker does the filesystem resolution and hands in the resolved paths, so the monitor is pure judgment over strings. It canonicalizes every proposed path (Unicode normalization, separator and verbatim-prefix handling, lexical traversal collapse), cross-checks it against the broker-resolved form, and admits a write only if it lands inside the contract's frozen write-set and clears a set of never-exempt forbidden prefixes. A proposal carrying unresolved unknowns is denied outright. Guessing is not a legal move.

The standalone monitor runs against a frozen corpus of path forms: directory traversal, symlink escape, case-fold collisions, Windows reserved device names, alternate-data-stream targets. In the target integration, the broker supplies resolved paths and invokes the same gate at receive and use time. The reviewed composition does not execute that broker sequence.

Where the gate belongs: the contracted change path

This is the target sequence, not the current production path. Each privileged transition requires authority-owned evidence, and each failed gate blocks the mutation without converting missing evidence into a pass.

    repository authority

The core of that flow, in shape

# the gate every agent proposal passes. deny by default.
def on_proposal(env):
    if not registry.valid_token(env.worktree, env.token):
        return deny("TOKEN_INVALID")         # not your sandbox
    if registry.work_unit(env.worktree) != env.work_unit:
        return deny("WORKTREE_MISMATCH")     # not your work-unit
    plan = contracts.frozen_plan(env.work_unit)
    if plan is None:
        return deny("PLAN_NOT_FROZEN")       # no freeze, no work

    v = authorize(env.paths, plan)           # declared intent
    if v.denied: return deny("AT_RECEIVE", v)

    resolved = broker.pull(env.worktree, env.paths)
    v = authorize(resolved, plan)            # use-time: catch a swap
    if v.denied: return deny("AT_PULL", v)      # symlink / repath escape

    broker.materialize(v.canonical_map)      # only via the monitor's map
    return broker.open_pr(...)             # merge waits on a verdict
    # every branch above leaves a receipt (I11)

03The invariants

Eleven frozen target invariants. Individual components have tests, but end-to-end enforcement is not active around the current coding path.

Target-state requirements: the list describes what the composed system must enforce. It is not a claim that the current runtime already enforces every item.
  1. I1No agent credentials. No repo, API, or signing credential is ever in an agent container's filesystem, environment, or reachable network.
  2. I2Sole writer. The broker must be the sole repository writer. Agents cannot push, and the broker only opens pull requests, never direct pushes to protected branches.
  3. I3No self-assigned privilege. Trust label, tier, and code-origin come from the path and the broker's own dispatch record, never from agent-supplied metadata.
  4. I4Verdicts verify themselves. The required merge check must re-fetch and hash-verify evidence against the exact commit; verdict identity is distinct from PR-author identity, and neither can approve.
  5. I5Boundary paths need a human. Any diff touching the contract, kernel, or CI paths requires owner review; in-scope diffs auto-merge on a green verified check only.
  6. I6Out-of-write-set never becomes a PR. Denied at receive; widening scope is a new owner-frozen plan.
  7. I7Isolation never degrades. A workload that cannot run at its assigned grade fails visibly; it is never demoted to a weaker sandbox.
  8. I8Read-back is the only truth. No inbound webhook listener exists; any future event is a hint that triggers an API read-back, never a fact.
  9. I9Keys off the execution host. No key material ever resides where untrusted code runs.
  10. I10Unresolved unknowns block mutation. In the target path, a mutating proposal with open unknowns must be denied. That is enforced by sequencing, not by appeal to model intent.
  11. I11Every privileged event leaves a receipt. Freezes, approvals, PR opens, verdicts, merges, denials, and worktree lifecycle events must leave authority-owned evidence. The current composition has not demonstrated that obligation end to end.

05The target trust-critical build lane

The intended construction procedure. Component and module evidence exists, but the current composition does not govern its own construction end to end.

  1. Two independent authors.

    One model writes the tests and a difficult input corpus. A separate model writes the code. Neither sees the other's work, and both work only from the frozen contract. First-contact agreement is a convergence observation; trust still requires independent evidence and the applicable authority decision.

  2. Adjudicate, don't assume.

    The orchestrator checks the strongest claims against the source and sorts each disagreement into one of three buckets: a real defect, a hardening, or a contract ambiguity to reconcile. Changing frozen behavior is the owner's call.

  3. Independent holdout.

    The target lane uses a separately authored holdout outside the builder's view and records its catch rate. Current holdout evidence is scoped to component and module runs; composition-level holdout verification remains pending.

  4. Ship through the real gates.

    Once the broker, exact-diff human-control path, independent verification, and repository integration are wired, a change must move through a broker-authored pull request. The current composition has not demonstrated this path.

06Verification & evidence

The target verification contract is deterministic where possible and reserves model judgment for cases where a checker cannot decide.

The completed system must emit an artifact-bound evidence bundle, have a separate oracle identity attest it, and independently re-verify the evidence before release. It must also pass the defined end-to-end canary schedule. Current evidence covers component and lane-level checks; the complete composition path and sustained canary criterion are not yet demonstrated.

Prior scoped component and module verification identified receipt, path, and authorization defects after visible tests were green. Those results do not establish end-to-end composition correctness; composition holdout verification is still required. Evidence stays bounded to what a run actually checked.

07Threat model & honest residuals

The documented target prioritizes accidental reliability failures; the current composition is blocked and does not claim a production security posture.

The contract records accepted residuals and planned hardening steps rather than hiding them. These include stronger workload isolation, channel authentication, operational availability, and receipt-key protection. Live enforcement of the isolation, broker, canary, and receipt paths has not been demonstrated for the current composition.

The later planes (execution, knowledge, oracles, learning, comms) are designed at the master-contract level but not yet fully sub-contracted, so their scope isn't claimed as known. And the value of the whole thing is exactly proportional to whether the contracts capture real intent and the gates catch real failures. The rigor has to stay real, or it's just overhead.
