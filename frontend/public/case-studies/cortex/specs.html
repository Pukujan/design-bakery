01System model

Cortex is organized as planes of modules, each governed by a frozen contract. The kernel is the trust root every later plane stands on.

Nothing an agent proposes reaches the repository directly. An agent runs in a sealed container holding zero credentials and submits a typed proposal over one mediated channel. A single privileged process — the broker — is the only writer: it loads the owner-frozen contract for that work-unit, passes the proposal through the reference monitor, materializes an approved change only through the monitor's canonical mapping, and opens a pull request. Merge is gated on a deterministic verdict from a separate identity.

The kernel itself is the one acknowledged exception to contract-first construction: the machinery that enforces contracts cannot enforce its own creation, so Phase 0 is built by hand under a declared temporary mode with the human as manual contract authority. From Phase A onward, contract-first applies with no exceptions.

02The reference monitor

authorize() is a pure, deny-by-default function — the single gate every mediated request and every worktree pull passes.

It takes a proposal and the frozen contract, and answers exactly one question: may the broker materialize this change? No model, no judge, no I/O touches the verdict — the broker performs filesystem resolution and hands in the resolved paths; the monitor is pure judgment over strings. It canonicalizes every proposed path (Unicode normalization, separator and verbatim-prefix handling, lexical traversal collapse) and cross-checks it against the broker-resolved form, then admits a write only if it lands inside the contract's frozen write-set and clears a set of never-exempt forbidden prefixes. A proposal carrying unresolved unknowns is denied outright — guessing is not a legal transition.

The monitor is exercised against a frozen corpus of adversarial path forms — directory traversal, symlink escape, case-fold collisions, Windows reserved device names, alternate-data-stream targets — that grows every time an adversarial pass finds a new one.

03The invariants

Eleven mechanically-testable properties. Together they are the acceptance checklist and the daily self-test's assertion list.

  1. I1No agent credentials. No repo, API, or signing credential is ever in an agent container's filesystem, environment, or reachable network.
  2. I2Sole writer. Only the broker writes the repo; agents cannot push, and the broker only opens pull requests — never direct pushes to protected branches.
  3. I3No self-assigned privilege. Trust label, tier, and code-origin are derived from path and the broker's own dispatch record — never from agent-supplied metadata.
  4. I4Verdicts verify themselves. The required merge check re-fetches and hash-verifies the evidence against the exact commit; verdict identity is distinct from PR-author identity, and neither can approve.
  5. I5Boundary paths need a human. Any diff touching the contract, kernel, or CI paths requires owner review; in-scope diffs auto-merge on a green verified check only.
  6. I6Out-of-write-set never becomes a PR. Denied at receive; widening scope is a new owner-frozen plan.
  7. I7Isolation never degrades. A workload that cannot run at its assigned grade fails visibly; it is never demoted to a weaker sandbox.
  8. I8Read-back is the only truth. No inbound webhook listener exists; any future event is a hint that triggers an API read-back, never a fact.
  9. I9Keys off the execution host. No key material ever resides where untrusted code runs.
  10. I10Unresolved unknowns block mutation. A mutating proposal with open unknowns is denied — enforced by sequencing, not by appeal to intent.
  11. I11Every privileged event leaves a receipt. Freezes, approvals, PR opens, verdicts, merges, denials, worktree lifecycle events — each minted only by the broker or oracle process.

05The trust-critical build lane

How a kernel module is built so that an independent adversary — plus the owner reviewing the boundary — could not find a gap.

  1. Two independent authors.

    A non-implementer writes the tests and an adversarial input corpus; a separate implementer writes the code. Neither sees the other's work — both work from the frozen contract. High first-contact convergence is the trust signal.

  2. Adjudicate, don't assume.

    The orchestrator verifies the strongest claims against source and classifies each disagreement: real defect, hardening, or a contract ambiguity that needs reconciliation. A frozen-behavior change is an owner decision.

  3. Sealed-holdout ratchet.

    A third model authors an adversarial holdout kept outside the repository — no agent can study it. It must kill 100% of seeded regression probes and surface gaps the visible tests missed. Every gap becomes a permanent open test; the module only ever gets stronger.

  4. Ship through the real gates.

    The change lands as a pull request authored by the broker's own identity, reviewed and approved by the owner. The system governs its own construction — code, tests, contract, and receipt move together.

06Verification & evidence

Deterministic where possible; a judge only where syntax genuinely cannot decide.

Every verdict emits a universal evidence bundle — exact model id, commit, image digest, dataset and oracle version, artifact hashes, verdict, and abstention — stored on a dedicated branch by the broker and hash-attested by a separate oracle identity, then independently re-verified by a required CI action. A daily canary exercises the whole path through the real machinery and pages the owner if any gate has gone soft; a module is not "done" until the canary runs green for three consecutive days.

On this project the sealed-holdout ratchet has already found a receipt-replay hole and nine path-handling gaps in code that had passed every visible test and merged. The slow adversarial verification is not overhead — it is the product.

07Threat model & honest residuals

The current posture is reliability-now, security-ready: the modelled adversary is a faulty or lazy agent — accidental reach — not a determined attacker.

Some residuals are accepted for now and recorded rather than hidden, each with a named hardening step on the ladder to a stronger posture: a determined sandbox escape could tamper with a sibling worktree on the same host (bounded by isolation grade and canary detection); channel authentication is boring bearer tokens behind a swap-ready seam; the broker and canary live on the owner's machine, so work queues while it is off. The receipt mint is tamper-evident, keyed by a local secret — honestly not tamper-proof against a party who also holds the key.

Later planes — execution, knowledge, oracles, learning, comms — are designed at the master-contract level but not yet fully sub-contracted; their scope is not yet claimed as known. The value of the whole system is exactly proportional to whether the contracts capture true intent and the gates catch true failures — the rigor has to stay real, or it is only overhead.
