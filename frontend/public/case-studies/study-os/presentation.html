The learner problem

“Wrong” hides a lot of different struggles.

“I get the idea. I just can't write it.”

“Why did they name it that?”

“I followed it until this step.”

“Can you show me what's changing?”

Those are different problems. They should not get the same lesson.

The AI-era market gap

AI made explanations infinite.

Another analogy, diagram, walkthrough or code sample can appear in seconds.

The hard problem moved to: which explanation should this learner see now?

Most products can generate more teaching material. Study OS is exploring how to choose and evaluate the intervention itself.

Real learning session

A Two Sum session made the problem concrete.

EXTERNAL FORM
for i in range(len(nums)):
    value = nums[i]
    ...
LEARNER-PROPOSED FORM
for i, value in enumerate(nums):
    ...

The learner already knew enumerate. In this moment, a major part of the friction was decoding somebody else's representation while also reasoning about the algorithm.

The teaching can create friction too

Then one variable name became the lesson.

seen→number_to_index→box

For this learner, seen already meant “set.” The code used it for a dictionary. The name was valid, but it was pulling attention away from the thing being learned.

The learner is not always the only thing that can fail. The explanation can fail too.

The product vision

Your AI tutor should learn from what confused you too.

01You tryStart from what you can already do.
02Friction appearsConcept, syntax, terminology, state, source convention or translation.
03Change the formTry a diagram, trace, simpler code, example or another representation.
04Watch what changesWhat helped becomes evidence for the next teaching decision.

The goal is not a fixed “learning style.” It is a partner that learns what helps this learner with this concept at this point in time.

The startup thesis

The next AI tutor probably won't win by knowing more.

Foundation models already know a lot. The opportunity is the layer between that intelligence and the learner: diagnosis, representation, memory, timing and evidence.

Generative AI solved abundance.

Explanations and examples are cheap to produce.

The scarce thing is a good teaching decision.

Research and provenance

The problem has a research basis. The product still has to prove itself.

Representations require cognitive translation.

Ainsworth's DeFT framework treats representation choice and coordination as part of the learning problem.

More representation is not automatically better.

A 2024 review found positive average effects with substantial variation across contexts.

Expert explanations can hide novice-relevant steps.

Programming research on subgoal-labeled examples supports exposing procedural structure.
