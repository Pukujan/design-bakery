The repo is not the first decision.

A technical project can be well researched and still begin with the wrong boundaries.

You can know the domain, understand the opportunity, and still skip the practical work that keeps implementation honest: what is in scope, what should be reused, which invariants matter, how success will be tested, and how the next person or agent resumes without reconstructing the whole conversation.

Drawing set / project preflight

PAM turns “we should probably remember that” into project-specific obligations.

It routes reusable methodology modules based on declared project facts. The point is not to force every technique onto every project. The point is to stop important project disciplines from existing only in someone's memory or prompt history.

SCOPEWhat are we building now? What attractive adjacent work is explicitly not part of this horizon?
REUSEWhat concrete systems and assets did we actually search before authorizing bespoke work?
PLANNINGWhat outcome, architecture boundary, invariants, and material failure modes need to be durable?
VALIDATIONWhat evidence will count when somebody later says the requirement is satisfied?
CONTINUITYWhat exact state does the next human or agent need to continue without guessing?
Why the evidence matters

A plan can be internally consistent and still be built on work that never happened.

The shortcut

A real adopter produced a plausible build-vs-reuse record, but one material capability was compared against an abstract “generic quiz framework” instead of named, researched alternatives.

The correction

PAM versioned the method instead of silently rewriting history. The hardened contract requires traceable discovery, concrete candidates, asset search where relevant, and explicit evidence for a build-new decision.

The market shift

In Stack Overflow's 2025 survey, 84% use or plan to use AI in development, while 69% say they do not plan to use it for project planning. High-responsibility planning is not disappearing just because implementation is faster.

The boundary

PAM does not prove the research conclusion is true. It governs the projectization work that should happen once a human decides the research is mature enough to build from.

The position

AI can accelerate the drawing. PAM is trying to make sure somebody approved the building.
