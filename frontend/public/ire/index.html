Why the cheapest number misleads

The lowest price is not the decision.

A price ladder looks like a bargain until the first real task. The cheapest ask might have four units of supply behind it while the next step up has five hundred. A dashboard that shows only the minimum hides that, and your agent finds out at runtime.

How a pick gets made

Every row shows its work.

IRE is a small open-source ranking engine. A daily job feeds it InferHub's catalog and status data and publishes what comes out.

The policy is a file you can read. Weights and gate thresholds live in version control, so a change to the ranking shows up as a diff.

The near-free line sits at $0.10 per million tokens. Under it, price stops dominating and availability and reliability separate the candidates.

Read the price and supply spec ↗

1
Read the whole price ladder.Every listed ask and how much supply sits at it. The minimum is one point on that ladder.
2
Weigh price by supply.A cheap ask with almost no supply counts for less than a slightly higher one that many sellers offer.
3
Check health and the written rules.Health comes from InferHub's public status page. A model that breaks a rule, such as too few providers or no healthy route, keeps its row with the reason attached.
4
Publish a dated list.Once a day the result goes to a public JSON file, along with the commit and data hashes that produced it.
Use it with your own key

Plug in your own InferHub key in two minutes.

IRE doesn't sit between you and InferHub. You call InferHub directly with your own key and the route name from today's list, so we never see your key. The examples below use today's cheapest recommended route: alicn/deepseek-v4.1-flash.

Set your key once in your shell:export INFERHUB_API_KEY=...PowerShell: $env:INFERHUB_API_KEY = "..."
CLAUDE CODE
ANTHROPIC_BASE_URL=https://api.inferhub.dev \
ANTHROPIC_API_KEY=$INFERHUB_API_KEY \
ANTHROPIC_MODEL=alicn/deepseek-v4.1-flash \
claude

Uses the Anthropic-compatible endpoint. Leave /v1 off the base URL; Claude Code adds it.

LITELLM
model_list:
  - model_name: ire-cheap
    litellm_params:
      model: openai/alicn/deepseek-v4.1-flash
      api_base: https://api.inferhub.dev/v1
      api_key: os.environ/INFERHUB_API_KEY

The openai/ prefix tells LiteLLM which client to use. The route follows it unchanged.

CURL
curl https://api.inferhub.dev/v1/chat/completions \
  -H "Authorization: Bearer $INFERHUB_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"model":"alicn/deepseek-v4.1-flash",
       "messages":[{"role":"user","content":"hi"}]}'

The OpenAI-compatible endpoint, with your key as a Bearer token.

Picking a cx/ route? Read this first.

Routes that start with cx/ go through OpenAI Codex. On those, your system prompt reaches the model as a developer message, and a fixed instruction, "You are a helpful assistant.", fills the slot the upstream requires. Most chat use won't notice. If your tool depends on a strict system prompt, call /v1/responses instead of /v1/chat/completions. That endpoint keeps your instructions as you sent them.

Routes on cb/ and cbcn/ add a short system note ahead of yours. You can switch it off per key in InferHub under Dashboard → API keys → Prompt filtering.

Want a quick check first? From a copy of the repo, pnpm ire:doctor confirms your key is set without printing it, fetches today's list and tells you how old it is.

Let your scripts fetch today's pick on their own.

Today's list is one JSON file at a public URL, with no login. A launcher, a proxy config or an agent can read it at startup and pick a route without anyone in the loop.

Read this before you rely on it

What this page doesn't promise.

Every row is a ranking with its evidence attached. Here is where that evidence runs out.

Capability scores are rough for now.

They come from a carried-over prior with low confidence until fresh benchmark data exists. A model that's new to InferHub can show up unscored.

Prices move.

Each price is the lowest listed ask when the list was built. You pay what InferHub charges at the moment you call, and that can be more.

Health is platform-wide.

It comes from InferHub's public status page, so it says nothing about your account. A route that looked healthy at build time can fail an hour later.

Your workload isn't tested.

IRE ranks routes. It doesn't run your prompts or measure how often your requests succeed.

No privacy claims.

IRE says nothing about how any provider handles your data. Read each provider's terms for that.

It isn't a router.

Nothing is proxied and no key is stored. If a route fails, falling back to another one is up to your tool.

Use the list to choose faster, then check the live price on InferHub before a long or expensive run.
