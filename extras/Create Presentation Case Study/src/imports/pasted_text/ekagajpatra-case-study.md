## Overview

Ekagajpatra is a civic-tech platform built to simplify complex government, legal, and financial documentation for individuals, businesses, and professional consultants across Nepal.

I worked across product design, frontend engineering, fullstack architecture, and product development to help turn fragmented, broker-driven documentation workflows into a scalable digital platform.

The platform supported:

Individual citizens
Small businesses
Legal consultants
Financial consultants
Subscription-based B2B users

The system transformed paper-based documentation into guided, validated, and PDF-generated digital workflows. It was designed desktop-first for accuracy, review, and document visibility, while using responsive components that allowed mobile access without requiring separate codebases.

---

## Problem

Documentation workflows in Nepal were expensive, fragmented, and difficult to navigate.

Users often depended on informal brokers to complete forms. Businesses had recurring documentation needs but lacked organized digital tools. Legal and financial consultants worked through manual or disconnected systems. Errors were often discovered late, leading to costly rework.

From a product and engineering perspective, the challenge was not just to digitize forms. The real challenge was to design a system that could guide different users through complex workflows, validate information early, generate reliable documents, and scale across consumer and professional use cases.

## Product Design and UX Strategy

The product design challenge was to make complex documentation feel manageable.

I focused on turning intimidating forms into guided workflows with clear steps, contextual explanations, and visible progress. Instead of forcing users to understand legal or financial terminology upfront, the interface explained unfamiliar concepts at the moment they appeared.

The product experience was designed around:

Clear visual hierarchy
Step-by-step form progression
Contextual guidance and tooltips
Early validation feedback
Reduced cognitive load
Document preview and review flows
Dashboard-based workflows for professional users

The goal was to make the product feel less like a government form and more like a guided operating system for documentation.

The system separated:

## Frontend Engineering

The frontend was built with React, Next.js, TypeScript, and TailwindCSS.

I built a modular component system for:

Input fields
Multi-step forms
Progress indicators
Validation states
Error messages
Tooltips
Dashboard views
Document preview flows

The frontend handled complex form behavior, preserved user progress, surfaced missing information early, and prevented invalid document generation.

The architecture was desktop-first because users needed enough screen space to review long, detailed documentation. At the same time, reusable responsive components kept the platform mobile-ready without requiring separate mobile-specific workflows.

---

## Backend and Data Integration

The platform integrated frontend workflows with backend APIs and PostgreSQL-backed data models.

I collaborated on API contracts for:

Saving form progress
Retrieving user and business records
Submitting structured form data
Handling consultant and business workflows
Supporting reusable document templates
Managing subscription-based access

The data model needed to support multi-layered, tabular, and reusable information because government and legal documents often required repeated parties, business details, addresses, dates, and supporting fields.

The system was designed so that user input could move cleanly from form state to backend storage to PDF output.

## PDF and Document Generation

Document generation was one of the most important parts of the system.

The platform converted structured user input into standardized, submission-ready PDF documents. Before a document could be generated, the system checked required fields, validation status, and completion state.

The document generation workflow:

Structured user input into templates
Blocked output when required data was missing
Reduced manual document preparation
Generated PDFs accepted by government offices, legal firms, and financial institutions
Created repeatable document workflows for individuals and consultants

This made document generation a fullstack product problem, not just a frontend feature.

## Key Learnings

Fullstack product engineering requires understanding the user journey, not just the codebase.

Complex forms work better as guided workflows than static digital documents.

Frontend systems are responsible for data correctness, not just presentation.

Product design decisions shape backend and data requirements.

Document generation is a core workflow architecture problem.

Desktop-first design can still support responsive mobile access when the component system is intentional.

Multi-role SaaS platforms need clear separation of workflows, permissions, and user intent.
