## Goal

but pinned each component by hand. The stack now has a single certified version
set — the **release train** (`Pukujan/agent-stack-train`) — and adopters follow it
instead of copying pins. This task moves the installed stack onto the current
train, adds the adopter manifest, and makes CI fail when the manifest and the
train disagree.

## Notes

- **ACS version vs module version.** The ACS *system* is 0.2.0; the
  `multi-agent-hotload` *module* it ships is 0.1.0. The lock records the module
  version, which is why it reads 0.1.0 while the system is 0.2.0.
- **Installed from `25be219`, not the certified `589b0a9`.** The certified ACS
  commit carries a stale `stack-mesh.json` (PCM `197f7ba`, CGM `b487b48`) and
  refuses the current PCM/CGM checkouts. `25be219` is origin/main (a descendant
  of `589b0a9`) and its mesh matches the current train, so the installer verifies
  the right commits. The train certifies the default-branch head each refresh, so
  `25be219` is what the next refresh will certify.
- **OIO still cannot install on native Windows.** It needs descriptor-relative
  no-follow filesystem ops (`os.supports_dir_fd`, `O_NOFOLLOW`, `O_DIRECTORY`)
  and fails closed without them. Installed from WSL Ubuntu 22.04 against
  `/mnt/d/development/design-bakery.com`, using an LF-canonical worktree of OIO
  (`%LOCALAPPDATA%\acs\worktrees\oio-a4bba77`) because OIO records byte-exact
  SHA-256 hashes and `core.autocrlf=true` would rewrite them to CRLF.
- **OIO managed files are byte-identical** between the old pin `469adf1` and the
  train commit `a4bba77`; the OIO diff is only in its own CI/stack files. It was
  reinstalled anyway to satisfy the installer's state machine and prove freshness.
- Pinned dependency checkouts stay under `%LOCALAPPDATA%\acs\deps\` (ACS dev-root
  hygiene), not in the dev root.
